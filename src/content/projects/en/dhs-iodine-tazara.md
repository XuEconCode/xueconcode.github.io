## Background

This is a methods exercise: I replicated the data processing of a published empirical paper (not my own research) that uses the Tanzania DHS 2015–16. The point was not the findings themselves but turning the whole path from raw questionnaires to regression output into a pipeline that is reproducible, self-checking and portable.

## The pipeline

The project is a sequence of numbered scripts, each of which can be re-run on its own:

1. `00` inventory the raw files → `01` clean household, individual and lab-log data → `02` GIS distances → `03` merge into an analysis file;
2. `04` regressions in Stata → `05` black-and-white maps → `06` automated checks of key numbers → `07` auto-generated results summary.

## Design choices

- **Config-driven and portable**: variable names, paths and thresholds live in `config/variables.yaml`, so moving to another country means editing a single file.
- **Self-checking**: key numbers are written as assertions that fail loudly, and the results summary is generated by script, so the documentation always matches the data.
- **Reconciliation catches hidden bugs**: matching the lab log against the household file by barcode revealed an implied decimal that would have inflated a coefficient tenfold.
- **A team of agents**: four specialised sub-agents (documentation scout, cleaner, GIS, Stata runner) plus three custom commands, packaged as an installable plugin.
- **Safe to share**: every exported file was checked before release, restricted GPS coordinates were removed, and machine-specific paths were reduced to one setup command.
