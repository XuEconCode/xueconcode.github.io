## 缘起

这是一次方法练习：以一篇已发表的实证论文（并非我的研究）为对象，复现它基于坦桑尼亚 DHS 2015–16 数据的数据处理流程。重点不在研究结论本身，而在于把原始问卷到回归结果的整个过程，做成一条可复现、可自检、可迁移的流水线。

## 流水线

整个项目是一串编号脚本，每一步都可以单独重跑：

1. `00` 盘点原始数据包 → `01` 清洗户表、个体表与化验日志 → `02` GIS 测距 → `03` 合并成分析数据集；
2. `04` 在 Stata 中回归 → `05` 输出黑白学术地图 → `06` 自动核对关键数字 → `07` 自动生成结果摘要。

## 设计要点

- **配置外置，一键迁移**：变量名、路径与阈值集中在 `config/variables.yaml`，换一个国家只需修改这一个文件。
- **自动体检**：关键数字写成断言，改坏了立刻报警；结果摘要由脚本生成，文档里的数字始终等于当前数据。
- **对账发现隐藏问题**：用化验室日志与户表按条码对账，发现户表数值隐含一位小数，避免了 10 倍的单位错误。
- **多 Agent 分工**：文档侦察、清洗、GIS、Stata 回归四个子 Agent，加三个自定义命令，并打包成可安装插件。
- **安全分享**：发布前逐个检查导出文件，剔除受限的 GPS 坐标，把本机路径收敛成一条适配命令。

完整的协作过程见文章[《用 Claude Code 搭一条可迁移的实证数据流水线》](/writing/claude-code-dhs-pipeline/)。DHS 原始数据须向 The DHS Program 申请，不随代码仓库分发。
