经济史研究经常要用到大量国外的问卷调查，但这类数据通常有三道门槛：

1. **语言障碍**：问卷文档是外语，阅读难度比母语大得多；
2. **变量繁多**：一时半会很难理顺变量之间的逻辑关系；
3. **位置信息**：想把受访者的位置和地图结合起来分析，但 GIS 软件的操作有门槛。

这次我以一篇已发表的实证论文为练习对象（论文并非我的研究），用坦桑尼亚 DHS（人口与健康调查）数据复现它的数据处理流程。借这个项目，我想试验一件事：**能不能让 Claude Code 帮我搭一套标准化、可迁移的数据处理流程**。非洲很多国家的 DHS 数据都是公开的，如果设计得好，下次研究另一个国家时，只需要改一部分配置就能复用整套思路。

项目概况见[项目页](/projects/dhs-iodine-tazara/)。这篇文章讲的是过程：我是怎么和它协作的、每一步的 prompt 长什么样、中途踩了哪些坑。

## 先看全景

整条流水线由一串编号脚本组成，从 `Temp Data` 读、往 `Temp Data` 写，每一步都可以单独重跑：

| 顺序 | 脚本 | 做什么 |
| --- | --- | --- |
| 00 | `00_inventory.py` | 盘点原始数据：每个文件夹装的是什么、用不用 |
| 01 | `01_extract.py` 等 | 清洗户表、个体表、化验日志，构造缺碘 dummy |
| 02 | `02_distance.py` | GIS 测距：每个聚类点到铁路的最短距离 |
| 03 | `03_merge.py` | 合并成分析数据集 |
| 04 | `04_regress.do` | Stata 回归（Stata 只做这一步） |
| 05 | `05_map.py` | 黑白学术地图与距离数据 |
| 06 | `06_validate.py` | 体检：断言关键数字，输出 PASS / FAIL |
| 07 | `07_report.py` | 结论自动成文，外加拟合图 |

一句话概括：**清洗（把散在几张表里的碘数据理干净）+ 测距（用 GIS 算到铁路多远）+ 合并，然后回归、出图、自检**。换一个国家做同类研究，这张表一模一样，只需要把「坦赞铁路」换成别的设施，在配置文件里改几个变量名。

## 第一步：不急着写代码，先讨论框架

这是最反直觉、也最关键的一步。打开 Claude Code 后，我的第一句话不是「帮我清洗数据」，而是把目标讲清楚，然后问它会怎么设计：

> 这个文件里是我这个项目想达成的目标……我需要首先和你讨论你会如何设计框架完成以上目标……我现在个人觉得这个数据变量非常多以及复杂，是否需要考虑多 agent 合作呢？

这里我做了三件事：给它一份**可读的目标文档**，而不是口头交代两句；明确要求**先讨论、不要动手**；把自己的纠结（变量太多、要不要多 Agent）直接抛给它。

它没有立刻写代码，而是先派「侦察兵」把我的文件夹和数据扫了一遍，回了一份方案，并就几个该由我拍板的问题反问了我：

| 它问的 | 我的选择 |
| --- | --- |
| 多 Agent 是并行抢着干，还是专业分工 | 专业分工，顺便展示一套多 Agent 协作范式 |
| GIS 用 Python 还是纯 Stata | Python + GeoPandas，并指定本机解释器 |
| 这一轮只出蓝图，还是真的跑数据 | 真的动手跑 |
| 主结局变量用哪个 | 起初以盐碘化为主，后来按论文口径改为尿碘 |

**经验：把「该你定的」和「该模型定的」分开。** 研究设计（用哪个结局、怎么识别因果）是你的事；工程实现（用什么库、怎么组织脚本）可以放手让它提方案。好的模型会主动把前者反问给你，而不是替你瞎定。

我还补了一条总原则，后来证明非常重要：**复杂的清洗和计算优先用 Python，Stata 只做回归和最简单的数据筛选。**

## 第二步：用 CLAUDE.md 立规矩

讨论清楚后，第一个产物不是代码，而是项目根目录下的 `CLAUDE.md`。Claude Code 每次开新会话、每个被派出去的子 Agent，都会先读这个文件，所以它是主会话和所有分身的共同记忆。我写进去的核心规矩包括：

```text
- 复杂清洗 / 计算 / GIS → Python；Stata 只做回归 + 最简单筛选
- Raw Data 只读：可以帮我整理命名和路径，但绝不许改原始数据内容
- 脚本编号、幂等、可重跑；中间产物一律写进 Temp Data
- DHS 的特殊缺失码（994/995/996 等）必须显式处理，不能当成数字
- GPS 经纬度被 DHS 做过随机位移，距离是近似——结论里要注明
```

**经验：把踩过的坑和不可破的底线写进 CLAUDE.md。** 写一次，之后所有子 Agent 都会遵守，省去反复叮嘱，也能防止它手滑改坏原始数据。

## 第三步：多 Agent 重在分工，不在人海

我最初的想法是：变量这么多，是不是该开一堆 Agent 并行干？Claude Code 给了一个我认同的判断：

> 数据清洗管道本质上是顺序依赖的：清洗 → 合并 → 算距离 → 回归，每一步都吃上一步的产物。开几个 Agent 并行抢着写中间文件，最大的风险是产生两份不一致的中间数据集。「变量多」是知识和文档问题，不是并行计算问题。

所以最终的架构是**一条顺序主线 + 一支专业分工的团队**：主线是编号脚本，可复现、每步之间人都能检查；只把只读、可并行、不写同一份状态的活儿派给子 Agent。

| 子 Agent | 职责 |
| --- | --- |
| `recon` | 读变量文档、盘点文件夹（只读） |
| `cleaner` | 读数据、处理缺失码、构造结局变量、合并 |
| `geo` | 计算到铁路的距离、画黑白地图 |
| `stata-runner` | 跑回归并导出表格 |

派给文档侦察 Agent 的 prompt 骨架如下，可以直接照搬：

```text
你是本项目的「文档侦察」agent。任务：读 DHS 文档，产出一份精确的变量字典。
【只读，不要改任何文件】

请按这些组分别整理：
  1. 结局-碘：HV234 / HV234A / SHIOD / SBUIOD …… 每个都要报取值含义与缺失码
  2. 地理键：HV001（确认它对应 GPS 文件里的 DHSCLUST）
  3. 控制变量：城乡、财富、地区、户主性别与年龄……

.MAP / .FRQ 文件很大，请用 grep 搜具体变量名，不要整文件读。
最后给我一张表：变量 | 标签 | 取值 | 缺失码 | 来源文件。缺失码务必精确。
```

侦察兵回来后纠正了我一个大错：我一直以为碘数据在 `TZOB7ADT` 包里（而那个文件夹一开始根本没放进项目），它指出盐碘化其实在户表的 `HV234A`，还发现 `HV234`（PPM 那一列）**整列是空的**，不能用。这种「文档说有、数据里其实没有」的坑，靠人工翻几百页文档极易翻车，先让 Agent 扫一遍非常值得。

## 第四步：编号流水线与四个关键点

**1. 动手清洗前，先盘点。** DHS 解压出来是一堆缩写文件夹（`TZHR`、`TZPR`、`TZGE`、`TZOB`……），光看名字不知道哪个有用。`00_inventory.py` 只读每个数据文件的元信息，列出一张「哪张表是什么、用不用、为什么」的清单。这一步我第一版漏了，补上之后少走了很多弯路。

**2. 显式处理缺失码，遇到缺变量要优雅降级。** 「无盐 / 未检测」这类特殊码必须显式设为缺失。早期字典说尿碘在户表里，实际并没有；脚本没有直接崩掉，而是打印提示后跳过，把尿碘留到个体表里补做。

**3. GIS 测距先投影。** 每个聚类点到铁路的距离，就是从这个点向铁路线作垂线的长度。难点只有一个：经纬度的单位是「度」，不能直接当米算。所以要先把点和线一起从 `EPSG:4326` 投影到 `EPSG:32736`（UTM 36S，单位是米），再求最短距离，最后除以 1000 得到公里。

**4. 能对账的两个来源，一定要对一次账。** 化验室日志记录了盐样和尿样的「条码 → 碘值」。拿它和户表、个体表按条码对账：尿碘逐行相等，说明取数没问题；盐碘却全部满足「户表值 ≈ 日志值 × 10」。原来户表隐含一位小数（`402` 实为 `40.2 ppm`），直接用会让系数放大 10 倍。

回归按原论文的口径设定，Stata 只负责这一步：

```stata
use "Temp Data/03b_analysis_urine.dta", clear
gen lndist = ln(dist_railway_km)
regress iodine_deficient lndist, vce(cluster hv001)   // 线性概率模型
```

复现出的系数和分组统计与原论文报告的基本一致，说明整条流水线跑通了。

> 两个 Stata 小坑：stata-mcp 出于安全会拦截 `ssc install`，导表改用内置的 `putexcel`；`estimates restore` 之后 `r(table)` 会失效，p 值要在每个回归之后当场用 `test` 取。

## 第五步：让结果能自证

跑通不等于跑对。数据清洗最怕某天改了一行代码，结果被悄悄改坏了自己却不知道。所以我加了两步收尾。

`06_validate.py` 把一路验证过的关键事实写成自动断言：样本量必须是 4234，缺碘率必须约为 17.31%，盐碘条码对账必须一致，分距离带缺碘率必须单调递增……

```text
C2 尿碘子样本 N            PASS ✅ 4234
C3 缺碘患病率≈17.31%       PASS ✅ 0.1731
C5 盐碘条码对账            PASS ✅ 匹配 2986 条，最大差 0.000
C6 距离带缺碘率单调↑        PASS ✅ 0.0463 < 0.0696 < 0.1534 < 0.2275
通过 7/7
```

`07_report.py` 则让脚本自己算、自己把系数和梯度表写进结果摘要，**文档里的数字永远等于当前数据**。它还用 numpy 独立复算了一遍线性概率模型，结果和 Stata 对得上，相当于多了一道交叉验证。

## 第六步：可迁移，也要可分享

整套设计最值钱的地方，是换一个国家时几乎不用重写代码：放入新国家的数据包 → 跑盘点 → 按新变量名修改 `config/variables.yaml` → 重跑流水线。跑完体检 7 项全绿，就说明新国家的流程也通了。常用流程我做成了自定义命令（`/run-pipeline`、`/migrate-country`、`/new-outcome`），又把子 Agent 和命令一起打包成了可安装的插件。

但真到要把项目发出去时，我才发现：**一个在自己机器上完美运行的项目，直接发出去几乎必然跑不起来，还可能顺手闯个祸。** 发布前的体检一共查出四个问题：

1. **差点把不该发的数据发出去。** 一份我以为是「自己算的距离结果」的表里，其实原样带着 DHS 受限的 GPS 经纬度。修法是只公开聚类编号和距离，含经纬度的完整版留在本地、写进 `.gitignore`。
2. **硬编码路径。** 本机的解释器路径在文档和 prompt 里出现了 13 次，别人 clone 下来第一步就会失败。现在收敛成一条本机适配命令。
3. **`.gitignore` 把展示用的图表也挡住了。** 这两个文件夹加起来不到 1 MB，却是项目的门面，应当入库。
4. **缺少 LICENSE。** 补上了 MIT，并写清楚它只覆盖代码，不覆盖 DHS 数据。

**经验：可复现不等于可分享。** 体检全绿只说明「我能跑」；要做到「别人能跑」，还差本机适配、数据获取指引、合规边界和许可证。

## 写在最后

回头看，这次最有用的经验有这么几条：

1. **先讨论，再动手**：把目标写成文档交给它，让它先勘探数据、先提问，再写代码；
2. **动手前先盘点**：把每个文件夹装的是什么列成一张可复现的清单；
3. **分清谁拍板**：研究设计你来定，工程实现让它提方案；
4. **立 CLAUDE.md**：把规矩和踩过的坑写进去，所有会话共享；
5. **多 Agent 重在分工**：顺序的清洗管道保持单线，只把读文档这类只读的活儿外包；
6. **能对账就对账**：化验日志既证实了尿碘，又揪出了盐碘的 10 倍单位问题；
7. **让流水线自己检查自己**：关键数字写成断言，结论自动成文；
8. **分享前把每个文件打开看一眼**：靠记忆发现不了派生文件里夹带的原始数据。

完整代码与使用说明见 [GitHub 仓库](https://github.com/xwh6-0/dhs-iodine-tazara)。
